## 二、核心概念（用自己的话写，写完能合上笔记讲出来才算掌握）

### 1. Maven 多模块与版本仲裁
- 父 pom 的 `dependencyManagement` 只声明版本、不真正引入；子模块引用时不写版本号 → 全工程版本一致。
- 子模块之间依赖（mall-user 依赖 mall-common）必须先 `mvn install` 把公共模块装进本地仓库。

### 2. 三层架构
- Controller 接待员：收请求、调 Service、返回 Result。
- Service 业务员：业务规则放这里；Controller 的 import 里不应出现 mapper 包。
- Mapper 仓库管理员：只写 SQL。

### 3. 热部署 DevTools
- 改代码保存后自动重启（日志线程名会变成 `restartedMain`）；`optional=true` 打包时自动失效。

### 4. 统一返回体 Result<T>
- code/msg/data 三件套，前端只认一种格式；code=0 成功。

### 5. 日志
- @Slf4j + logback-spring.xml：控制台+文件双输出，按天+10MB 滚动，保留30天。
- 用 log.info/warn 代替 System.out，级别可控。

## 三、踩坑排查记录（真实过程，面试素材）

### 问题1：编译报错"找不到符号: 类 JsonIgnore"
- 环境/复现步骤：mvn compile 编译 mall-user 模块。
- 关键报错：`找不到符号 类 JsonIgnore 位置: 类 com.mall.user.entity.User`
- 排查过程：报错指向 User.java 第18行 → 检查发现用了 `@JsonIgnore` 但没写 `import com.fasterxml.jackson.annotation.JsonIgnore;`
- 根因：注解类来自 jackson-annotations 包（spring-boot-starter-web 已传递引入），依赖在但 import 漏了。
- 解决方案：补上 import，重新编译通过。
- 面试一句话总结：编译期"找不到符号"先看是缺依赖还是缺 import，Maven 传递依赖可在 IDEA 的 External Libraries 里确认。

### 问题2：单模块启动报 mall-common 依赖找不到
- 环境/复现步骤：`mvn -pl mall-user spring-boot:run` 单独启动用户服务。
- 关键报错：`Could not find artifact com.mall:mall-common:jar:1.0.0 in aliyunmaven`
- 排查过程：mall-user 依赖 mall-common，但本地仓库（.m2）里没有它的 1.0.0 jar；Maven 甚至去远程仓库（aliyun）找了也没有。
- 根因：多模块工程里，兄弟模块只有被 `mvn install` 安装进本地仓库后，才能被其他模块单独构建时解析到。
- 解决方案：先在根目录执行 `mvn install`，再单模块启动。
- 面试一句话总结：Maven 多模块项目单模块启动报"找不到兄弟模块"，是没 install 到本地仓库，用 -pl 配合 install 或先整体 install 解决。

## 四、MySQL 知识点

- 一服务一库：db_user / db_product / db_order，为微服务"数据隔离"打底。
- `BIGINT AUTO_INCREMENT PRIMARY KEY`：自增主键。
- `VARCHAR(50) UNIQUE`：用户名唯一约束，数据库层面兜底。
- utf8mb4 字符集：支持 emoji，比 utf8 存得全。
- 后续任务会专门讲：DECIMAL 金额、事务、索引。

## 八、版本管理规则（自 V1.0 起生效）

> 2026-11-08 起本仓库采用以下版本约定，后续任务单遵守。

- **主分支线性开发**：日常开发全部在 main 分支上进行（本地与远程同名），不用分支区分版本。
- **Tag 定格里程碑**：阶段性任务全部收尾后打 annotated tag 并推送：
  ```bash
  git tag -a v1.0 -m "V1.0：多模块工程搭建 + user-service 用户查询接口交付"
  git push origin v1.0
  ```
- **版本号规则**：大阶段交付 v1.0 / v2.0 / v3.0…；阶段内小迭代打 v1.1、v1.2…
- **回看/对比**：`git checkout v1.0` 回看旧版；`git diff v1.0 v2.0` 对比版本差异；看完 `git checkout main` 回来。
- **文件名不带手工版本号**：版本交给 Git 管理，文档/代码文件名不再加 "v1.8" 之类后缀（避免 rename 造成的历史断裂）。
- 当前已定格：`v1.0` = 任务单#01 交付（多模块工程 + user-service 用户查询接口）。
