# 用户服务接口文档 v1.0

> 下发方：产品经理（验收）/ 前端对接用
> 服务：user-service（开发期直连 `http://localhost:8081`，阶段5接入网关后走 `http://localhost:9000`）

## 通用约定

- 所有接口返回统一 JSON 结构：

```json
{
  "code": 0,        // 0=成功，非0=业务失败
  "msg": "ok",      // 提示信息
  "data": {}        // 业务数据，可能为 null
}
```

- 出参中的时间统一为 `yyyy-MM-ddTHH:mm:ss`（ISO 格式）。
- **password 字段永远不出现在任何接口出参中**（安全红线）。

## 1. 根据ID查询用户

### 请求

```
GET /user/{id}
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| id | path | long | 是 | 用户ID |

### 响应示例（成功，HTTP 200）

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 1,
    "username": "zhangsan",
    "phone": "13800000001",
    "createTime": "2026-11-08T17:18:10"
  }
}
```

### 响应示例（用户不存在）

```json
{ "code": 1001, "msg": "用户不存在", "data": null }
```

> 备注：v1.1 起引入全局异常处理，业务失败统一返回错误码（1001 用户不存在、5000 系统异常），不再返回 code=0 + data=null。

## 验收用例（提测前请自测）

| 用例 | 请求 | 预期 |
|---|---|---|
| 正常 | GET /user/1 | code=0，data.username=zhangsan，**无 password 字段** |
| 边界 | GET /user/2 | code=0，data.username=lisi |
| 异常 | GET /user/999 | HTTP 200，code=1001，msg=用户不存在 |
