# 01 楼层路线与验收

> 主路线，每层都必须有新技术点（不允许重复 CRUD）。当前建到哪一层看下面的状态列。

## 路线表

| 层 | 模块 | 触发问题 | 新技术点 | 验收标志 | 状态 |
|---|---|---|---|---|---|
| **L0 地基** | mall-common + mall-user + mall-product | 单服务增删改查 | 三层架构五件套 + MyBatis 注解 SQL + Lombok + Maven 多模块 | 五件套能白纸默写 | ✅ |
| **L1 异常框架** | mall-common | 错误响应散乱 | `Result` / `ErrorCode` / `BizException` / `GlobalExceptionHandler` 四件套 | 原理讲透 + 默写 3 遍 | ✅ |
| **L2 订单 + RestTemplate** | mall-order | 订单要用户 + 商品，不许连别人库 | `RestTemplate` HTTP 调用 + DTO + Service 编排 + 调用容错 | 下单落库；关 product 得到友好失败 | ✅ |
| **L3 Nacos + Feign** | 全部 | 地址写死、手拼 URL 易错 | Nacos 注册中心 + `@EnableFeignClients` + `@FeignClient` | 代码里不再出现 `localhost:8082`；停 product 得到 2001 | ✅ |
| **L4 Sentinel** | 全部 | 下游挂上游跟着死；恶意流量 | Sentinel 控制台 + `@SentinelResource` + fallback + blockHandler + QPS 规则 | QPS=10 第 11 次被拦；停 product 走 fallback | ✅ |
| **L5 Redis 缓存** | mall-product | 每次查库，并发扛不住 | Redis + Spring Data Redis + `@Cacheable` + TTL/JSON + 空值缓存 + `@CacheEvict` | 第二次查询零 SQL、方法体零执行；改价后缓存失效 | ✅（L5-1~L5-5） |
| **L6 JWT 鉴权** | mall-user | 谁在下单 | jjwt（RS256 + JWKS）+ BCrypt + 拦截器验 token + ThreadLocal + RBAC | 登录拿 token → 带 token 下单 → 解析出 userId | ✅（L6-1~L6-6） |
| **L7 Gateway** | mall-gateway | 前端记 N 个端口 | Gateway 路由 + 全局过滤器统一验 JWT + 内置限流 | 所有请求只打 9000 | ✅（L7-1~L7-5） |
| **L8 MySQL 优化** | mall-order | 深翻页慢、filesort | 联合索引 + 延迟关联/游标分页 + 按月分区 + 造 10 万数据 | explain 前后对比 | 进行中（L8-1 完成） |
| **L9 并发与一致性** | order/product | 超卖、串行慢 | 线程池 + CompletableFuture + 号段发号器 + Lua 扣减 | 压测不超卖 | 未开始 |
| **L10 SpringDoc + JSR303** | 全部 | 文档过时、校验散落 | SpringDoc + `@Valid` + JSR303 | Swagger 可在线调试 | 未开始 |

## 三条关键线

- ★ **微服务成立线**（L2）：服务间 HTTP 协作、不共享数据库
- ★ **Spring Cloud Alibaba 全家桶线**（L3 + L4）：Nacos + Feign + Sentinel
- ★ **面试标准线**（L3 + L7）：注册中心 + 网关

## 版本约定（2026-11-20 已核对）

- Boot **4.1.2** → Spring Cloud **2025.1.4** → Spring Cloud Alibaba **2025.1.0.0**
- Nacos Server **3.3.0**：服务端 8848，控制台 8080
- 父 POM 只导 Cloud BOM；SCA 只给 starter 写显式版本（整包导 SCA BOM 会把 Cloud 顶回 2025.1.0）
- 兜底：跑不通就全工程降到 Boot 3.5.x + Cloud 2025.0.x + SCA 2025.0.0.0，业务代码基本不改
