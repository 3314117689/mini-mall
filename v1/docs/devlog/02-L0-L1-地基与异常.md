# 02 L0 地基 + L1 异常框架

## 一、L0：`GET /product/1` 的数据全链路

**命令入场**：`GET http://localhost:8082/product/1`

### 调用链（先记这张表）

| 顺序 | 谁 | 干什么 |
|---|---|---|
| 1 | Tomcat 线程 | 收到请求，按路径找到 Controller 方法 |
| 2 | `ProductController.getById` | 接收参数 `id` |
| 3 | `ProductServiceImpl.getById` | 判空、决定成功还是抛异常 |
| 4 | `ProductMapper.selectById` | 接口 + 注解 SQL，由 MyBatis 执行 |
| 5 | MySQL | 返回一行或 0 行 |
| 6 | `Result.ok` | 包装成统一返回体 |
| 7 | 框架（Spring MVC） | 转 JSON 写回浏览器 |

### 数据编号与形状变化

| 编号 | 数据 | 初始形状 | 谁产生 | 去向 |
|---|---|---|---|---|
| `[D1]` | 商品 id | `"1"`（String，来自 URL） | 浏览器 | 框架转成 `1L` 塞进 Controller 参数 |
| `[D2]` | 商品对象 | `Product{id=1,...}` 或 `null` | MyBatis（查库） | 进 `ProductServiceImpl.getById` 的 `product` 变量 |
| `[D3]` | 返回体 | `Result{code,msg,data}` | `Result.ok` | 作为 Controller 返回值交给框架 |
| `[D4]` | 响应文本 | JSON 字符串 | 框架序列化 | 浏览器 |

### 两条出路（L0 已建立，L1 完善）

| 出路 | 触发 | 谁处理 | `[D4]` |
|---|---|---|---|
| 正常 | `[D2]` 是 `Product` 对象 | `Result.ok` | `{"code":0,"data":{...},"msg":"ok"}` |
| 商品不存在 | `[D2]` 是 `null` | `ProductServiceImpl` 抛 `BizException` → `GlobalExceptionHandler` | `{"code":1002,"msg":"商品不存在"}` |

> 关键：`throw` 之后，Controller 里 `Result.ok(...)` **不执行**——这就是 L1 要补的那条路。

## 二、L0：`@Autowired` 注入的心智模型（用户已确认）

1. 注入了就**只管用**，其余全是框架做的。
2. 字段只声明不赋值就是 `null`，没注入就调 = **空指针**。
3. 接口（如 `ProductMapper`）源码里没有实现类，`new` 不出来，**只能靠框架注入**。
4. 两个时刻：**启动期**框架执行"字段 = 容器里的对象"（源码里看不到）；**请求期**你只写调用语句。
5. 每层只注入下一层：Controller → Service → Mapper。
6. 调接口方法 = 直接执行实现类的方法体，中间没有"先执行接口"。
7. `return Result.ok(productService.getById(id))` **从里往外**执行。

## 三、L1：异常四件套的链路

**默写顺序（依赖顺序）**：`Result` → `ErrorCode` → `BizException` → `GlobalExceptionHandler` → Service 里 `throw`

### 异常路径（`[D1] = 999L`）

1. `ProductServiceImpl.getById` 第 32 行 `if (product == null)` 为 true。
2. 第 33 行打 warn；第 34 行 `throw new BizException(ErrorCode.PRODUCT_NOT_FOUND)`。
3. `BizException` 构造器把枚举拆成 `code=1002`、`message="商品不存在"`。
4. 异常沿调用链往回飞：`ProductServiceImpl.getById` → `ProductController.getById` → 框架。
5. `GlobalExceptionHandler` 的 `@ExceptionHandler(BizException.class)` 接住 → `Result.fail(1002,"商品不存在")`。
6. `[D3] = Result{code=1002,...}` → `[D4] = {"code":1002,"msg":"商品不存在"}`。

### 正常路径

`[D2]` 非 null → 跳过 if → `return product` → `Result.ok` → `code=0`。

### 三个面试速答

- 为什么继承 `RuntimeException`：受检异常会污染所有方法签名，业务层本来也不打算接。
- 为什么 HTTP 仍返回 200：全工程约定前端只看 body 里的 `code`。
- 为什么 warn 和 error 分开：业务失败是预期内，一行 warn；兜底是意外故障，error 带堆栈。
