## 写作规范（写本目录任何一章都必须遵守）

1. **一条真实命令为轴**：写清方法 + 路径 + 参数真实值（如 `GET /product/2`）。
2. **分岔先行**：先列全部结局和分岔点，再逐个结局走。
3. **数据编号**：`[D1]`~`[Dn]`，每步写 `当前值 · 来源 · 去向`。
4. **调用关系不断**：开头给调用链；每次返回写明回到哪个类的哪一行。
5. **禁止省略**：不写"有值/没值/处理一下"，写具体变量和值。
6. **真实类名 + 归属**：不用外号；标"本项目 / 哪个框架"。
7. **行号只写核实过的**：没核实的写 `类名.方法名 + 文件`，不臆造行号。
8. **框架只讲动作**：对数据有影响才点类名。
